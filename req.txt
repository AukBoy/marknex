1.Introduction 
1.1 Purpose 
The purpose of this project is to develop MarkNex, an AI-Based Personal Teacher Assistant designed to 
automate the marking of handwritten answer scripts and generate personalized feedback for students 
and teachers. 
In Sri Lankan schools, manual marking of answer scripts is time-consuming, repetitive, and prone to 
inconsistencies. Teachers often struggle to provide timely and detailed feedback due to heavy workloads. 
Existing digital grading systems mainly rely on traditional Optical Character Recognition (OCR) methods, 
which perform poorly when interpreting handwritten responses and do not provide adaptive, concept-
level feedback. 
This project aims to address these challenges by developing a multimodal Large Language Model (LLM)-
powered system capable of: 
• 
Reading handwritten answers directly from scanned images. 
• 
Converting handwritten responses into structured digital text. 
• 
Evaluating answers based on predefined marking schemes. 
• 
Assigning marks with a confidence score. 
• 
Flagging low-confidence answers for manual teacher review. 
• 
Generating personalized student reports. 
• 
Providing teachers with class-level analytics and insights. 
The system is intended to: 
• 
Reduce teacher workload. 
• 
Improve grading efficiency and consistency. 
• 
Provide actionable learning insights. 
• 
Enhance overall teaching and learning outcomes.

 1.4 Product Scope 
MarkNex is an AI-powered web-based application designed to assist teachers in automatically evaluating 
handwritten Handwritten answer scripts. 
Core Scope of the Product 
The system will: 
1. Allow teachers to upload scanned images of student answer sheets. 
2. Use a multimodal Large Language Model (LLM) to interpret handwritten responses.

4. Compare responses against predefined marking schemes and model answers.

2.2.1 High-Level System Diagram 
 
 
The MarkNex system follows a structured and sequential workflow to ensure secure, accurate, and 
efficient automated evaluation of handwritten answer scripts. 
The process begins with user authentication. The teacher accesses the web-based interface and enters 
valid login credentials. The backend server verifies these credentials against the stored database records. 
After successful verification, the system establishes a secure session. 
11 
 
Next, the teacher uploads scanned answer scripts in supported formats such as PDF, JPG, or PNG. The 
system associates each script with relevant metadata, including student identification details, subject, 
examination information, and marking scheme references. It stores the uploaded files in a secure file 
storage system and records the corresponding metadata in the central database to ensure traceability 
and structured processing. 
After the upload, the backend server sends the script to the AI Evaluation Engine for automated 
assessment. The AI component preprocesses the image and performs handwriting recognition to convert 
the scanned content into structured digital text. It then compares the extracted text with predefined 
marking schemes using rule-based logic and semantic similarity techniques. Based on this comparison, 
the system assigns marks to each question, calculates the total score, and generates a confidence score 
to measure the reliability of the evaluation. 
If the confidence score exceeds the predefined threshold, the system automatically finalizes the marks 
and stores them in the database. If the confidence score falls below the acceptable level, the system 
flags the evaluation for manual review. It notifies the teacher and provides access to a review interface. 
The interface displays the original script, extracted text, AI-generated marks, and marking scheme 
references. The teacher can confirm, modify, or override the assigned marks before submitting the final 
evaluation. 
After completing the evaluation, the system generates detailed reports. These reports include student-
level feedback, topic-wise performance summaries, and class-level analytical dashboards. The system 
securely stores all finalized marks, feedback, confidence scores, and historical performance data in the 
database to support long-term academic tracking and performance analysis. 
This workflow integrates artificial intelligence with human oversight. It improves efficiency while 
maintaining fairness and reliability in the assessment process.

2.6 User Documentation 
The MarkNex system will be delivered with comprehensive user documentation to ensure that all users 
can effectively understand, operate, and maintain the system. The documentation is designed to support 
teachers, system administrators, and technical personnel by providing clear operational guidelines, 
technical references, and training resources. 
2.6.1 User Manual 
A detailed user manual will be provided as the primary reference document for teachers and authorized 
users. This manual will describe the overall system overview, including its purpose and key 
functionalities. It will explain the login and authentication process, step-by-step instructions for 
uploading scanned answer scripts, procedures for reviewing AI-flagged answers, and guidelines for 
generating and downloading evaluation reports. In addition, the manual will include a dashboard 
interpretation guide to help users understand performance analytics, summaries, and student insights. 
The user manual will be available as a PDF document and as a digital soft copy accessible within the 
system. 
2.6.2 Quick Start Guide 
A Quick Start Guide will be developed to assist first-time users in quickly understanding how to operate 
the system. This guide will provide simple step-by-step instructions for initial login and basic system 
usage. It will outline the overall workflow of uploading scripts, reviewing results, and generating reports. 
It will also include solutions to common troubleshooting issues that users may encounter. The Quick 
Start Guide will be available as a printable PDF and as a web-based help page integrated into the system. 
17 
 
2.6.3 Online Help System 
An Online Help System will be embedded within the MarkNex interface to provide real-time assistance. 
This will include tooltips displayed when users hover over specific features, context-sensitive help 
messages that appear based on user actions, and an FAQ section accessible from the system dashboard. 
This integrated support system ensures that users can receive immediate guidance without leaving the 
application. 
2.6.4 Technical Documentation 
Technical documentation will be prepared for system administrators, developers, and IT support staff 
responsible for maintaining and deploying the system. This documentation will include a detailed system 
architecture overview explaining the structural design of the application. It will provide a database 
schema description outlining data structures and relationships. Additionally, API documentation will 
describe endpoints, request formats, and response structures using a standard documentation format 
such as Swagger/OpenAPI. A deployment guide will also be included to explain installation, 
configuration, and hosting procedures. The technical documentation will be available in PDF or 
Markdown format. 
2.6.5 Training Materials 
Training materials will be provided to ensure effective system adoption among teachers. These materials 
will include structured presentation slides for training sessions, a demonstration video explaining the 
complete system workflow, and a sample answer script walkthrough to illustrate the marking and 
evaluation process. These resources will help users gain practical knowledge and confidence in using the 
MarkNex system efficiently. 
 
2.7 Assumptions and Dependencies 
2.7.1 Assumptions 
This section outlines the key assumptions and dependencies identified during the preparation of the 
Software Requirements Specification (SRS) for the MarkNex system. These assumptions define the 
expected conditions under which the system will operate. If any of these assumptions are invalidated, 
the system requirements, design, or implementation strategy may require revision. 
Technical Assumptions 
It is assumed that the multimodal Large Language Model (LLM) selected for handwritten answer 
interpretation will provide sufficiently accurate and reliable output when evaluating handwritten answer 
scripts. The system assumes that the AI model is capable of interpreting handwritten content without 
relying exclusively on traditional Optical Character Recognition (OCR) methods. 
It is further assumed that the external API services required for AI model integration will remain stable, 
accessible, and compatible throughout the development and deployment phases. The system is 
expected to operate in a stable internet-connected environment to support AI processing and data 
synchronization. 
18 
 
Additionally, it is assumed that uploaded answer scripts will be clearly scanned, properly aligned, and 
legible. The system assumes that image quality will meet minimum acceptable standards. Poor image 
quality, distortions, shadows, or blurred handwriting may negatively affect evaluation accuracy. 
Operational Assumptions 
It is assumed that teachers using the MarkNex system possess basic computer literacy, including the 
ability to log in, upload files, navigate dashboards, and download reports. 
The system follows a human-in-the-loop approach, assuming that teachers will review and validate 
answers flagged as low-confidence by the AI model. Final grading authority remains with the teacher. 
It is also assumed that schools will permit the use of AI-assisted grading systems within their academic 
processes. Furthermore, marking schemes and model answers required for evaluation will be properly 
structured and available in digital format to support automated analysis. 
Academic Assumptions 
The initial implementation of the system is aligned with the Sri Lankan national curriculum and the 
approved project charter. 
The evaluation logic assumes that answers follow structured solution formats, including clear step-by-
step problem-solving approaches that are typical in structured assessments. 
 
It is assumed that the system will primarily be used for both formative and summative assessments 
within a controlled school environment. 
Development Assumptions 
It is assumed that all development team members will complete their assigned responsibilities as 
defined in the approved project charter and timeline. 
The availability of appropriate datasets for training, validation, and testing of the AI model is assumed. 
These datasets are expected to represent realistic student handwriting samples and curriculum-aligned 
mathematical problems. 
It is also assumed that the development timeline is aligned with the university’s final year project 
schedule and that required academic milestones will be met as planned. 
2.7.2 Dependencies 
The MarkNex system relies on several external components, technologies, and institutional approvals. 
Changes or failures in these dependencies may directly affect system performance, availability, or 
functionality. 
Third-Party Dependencies 
The system depends on a multimodal Large Language Model (LLM) service provider for handwritten 
answer interpretation and AI-based evaluation. 
19 
 
It also depends on a cloud hosting platform for application deployment and scalable computing 
resources. A web server and database management system are required for handling user requests and 
data storage. 
Secure communication between system components relies on API frameworks, particularly RESTful APIs. 
If any third-party service modifies pricing models, API structures, access policies, or availability, system 
functionality and sustainability may be impacted. 
 
Software Dependencies 
The backend implementation depends on a selected framework such as Python (Django) or Node.js. The 
frontend depends on technologies such as React or standard web technologies including HTML, CSS, and 
JavaScript. 
A Relational Database Management System (RDBMS), such as MySQL or PostgreSQL, is required for 
structured data storage. The system also depends on PDF and image processing libraries for handling 
uploaded answer scripts. 
Future updates, version incompatibilities, or deprecation of these technologies may affect system 
maintenance and long-term stability. 
Infrastructure Dependencies 
The system requires reliable internet connectivity to support AI inference and cloud-based processing. 
Adequate server computational resources are necessary to handle AI model execution efficiently. 
A secure hosting environment with HTTPS support is required to ensure data protection and secure 
communication. 
 
Institutional Dependencies 
The implementation of the MarkNex system depends on approval from the Department of ICT and the 
Faculty of Technology. 
The availability of real or sample student answer scripts is necessary for system testing and validation. If 
student data is used, appropriate ethical approval and data protection compliance must be obtained 
before deployment.

2.8 Data Flow Diagram - Level 1 
 
 
The Data Flow Diagram (DFD) Level 1 for the MarkNex system illustrates how data moves between 
external entities, internal processes, and data stores within the system. It decomposes the overall system 
into major functional processes and clearly shows how information flows during authentication, script 
evaluation, review, and report generation. 
The process begins when the teacher provides login credentials to the Authentication Process. The 
system verifies these credentials by interacting with the User Database. If the credentials are valid, the 
system grants access and allows the teacher to proceed. This process ensures secure access control and 
protects sensitive academic data. 
After authentication, the teacher uploads scanned answer scripts through the Script Upload and Storage 
process. The system stores the uploaded files in the Script Storage data store and records associated 
metadata, such as student information and exam details. Once the storage process is complete, the 
system forwards the script data to the AI Evaluation Process for automated marking. 
The AI Evaluation Process analyzes the uploaded script, converts handwritten content into digital text, 
compares it with the marking scheme, and assigns marks. The system stores the generated marks and 
confidence scores in the Marks and Reports Database. If the confidence level falls below the defined 
threshold, the system directs the data to the Manual Review and Adjustment process, where the teacher 
reviews flagged answers and modifies marks if necessary. The system then updates the database with 
the finalized results. 
Finally, the Report and Analytics Generation process retrieves evaluation data from the Marks and 
Reports Database and generates structured reports and performance analytics. The system delivers 
these reports to the teacher for review and academic decision-making. Overall, the DFD Level 1 clearly 
demonstrates how MarkNex manages data input, processing, storage, and output while maintaining 
controlled data movement between processes and data stores.

3.2 Hardware Interfaces 
This section describes the interaction between the MarkNex software system and the hardware 
components required for its operation. The system is primarily web-based and does not require 
specialized hardware beyond standard computing devices and optional scanning equipment. However, 
proper hardware support is necessary to ensure efficient system performance and accurate AI-based 
evaluation. 
Supported Hardware Devices 
The MarkNex system is designed to operate on commonly available computing devices. It supports 
desktop computers and laptops used by teachers to access the web-based interface. These devices must 
have a modern web browser and stable internet connectivity to ensure smooth interaction with the 
system. 
The system is deployed on cloud server infrastructure, which provides the computational resources 
required for data storage, processing, and AI model execution. The server environment may include high-
performance CPU and, where necessary, GPU resources to handle AI inference tasks efficiently. 
Optionally, flatbed scanners may be used to digitize handwritten answer scripts. Although scanning is not 
handled directly by the system, scanned documents must be converted into supported digital formats 
such as PDF, JPG, or PNG before being uploaded. 
 
Hardware Interaction Characteristics 
Teachers interact with scanner hardware externally to scan student answer scripts. The scanning process 
occurs outside the system environment. Once scanning is completed, the digitized answer scripts are 
uploaded to the MarkNex system through a web browser interface. 
Upon upload, the server processes the images using its computational resources. The AI model performs 
handwritten answer interpretation and evaluation using CPU and/or GPU capabilities available within the 
cloud infrastructure. 
The system does not directly control or manage hardware devices; instead, it relies on standard 
input/output mechanisms through web technologies to ensure compatibility and flexibility across 
different hardware configurations.

Operating System Interface

macOS. Since MarkNex is a web-based application, users interact with the system through a web 
browser. Therefore, no OS-specific dependencies shall affect user interaction, and no additional software 
installation is required on the client device beyond a supported browser.

3.4 Communication Interfaces 
This section describes the communication requirements of the MarkNex system, including network 
protocols, security mechanisms, data transfer standards, synchronization processes, and optional 
notification services. These requirements ensure secure, reliable, and efficient data exchange between 
system components. 
 
Network Communication 
The MarkNex system requires stable internet connectivity for proper operation, particularly for AI 
processing and cloud-based deployment. 
The system shall use standard web communication protocols, including HTTP and HTTPS. All 
communication between client devices, servers, and external AI services shall follow RESTful API 
principles for structured and scalable integration. 
Data exchanged between components shall be formatted using JSON (JavaScript Object Notation) to 
ensure interoperability and readability. 
All communications shall use HTTPS encryption to protect sensitive academic data during transmission. 
 
Security Requirements 
To ensure data protection and secure system operation, the following security measures shall be 
implemented: 
• 
TLS (Transport Layer Security) encryption for all client-server communication. 
• 
Token-based authentication mechanisms such as JSON Web Tokens (JWT) for secure user session 
validation. 
• 
Role-based access control (RBAC) to restrict system functionalities based on user roles (e.g., 
teacher, administrator). 
• 
Secure session management to prevent session hijacking and unauthorized access. 
• 
Encrypted password storage using hashing and salting techniques to prevent credential 
compromise. 
These measures ensure confidentiality, integrity, and secure access control within the system. 
 
Data Transfer Requirements 
The system shall enforce a configurable maximum file upload size limit to prevent server overload and 
ensure performance stability. 
25 
 
The system shall support batch uploading of multiple answer scripts to improve operational efficiency for 
teachers handling large class sizes. 
Where necessary, efficient image compression techniques may be applied before AI processing to 
optimize bandwidth usage and reduce processing time without significantly affecting image quality. 
 
Synchronization Mechanisms 
AI-based evaluation shall operate asynchronously. After uploading scripts, users shall not be required to 
wait on a locked interface. Instead, the system shall process submissions in the background. 
The system shall display clear processing status indicators (e.g., “Processing,” “Completed,” “Review 
Required”) to inform users about evaluation progress. 
Database transactions shall follow atomicity and consistency principles to ensure accurate storage of 
marks and evaluation data. 
An automatic save mechanism shall be implemented when teachers review and modify marks, ensuring 
that no reviewed data is lost due to unexpected interruptions. 
 
Email or Notification Services (Optional / Future Enhancement) 
As a future enhancement, the system may include email notifications to inform teachers when 
evaluations are completed. 
Additionally, the system shall support downloadable PDF reports for record-keeping and academic 
documentation purposes. 
These communication features will enhance usability, transparency, and workflow efficiency in future 
versions of the MarkNex system.

The MarkNex system shall meet the following performance requirements:

2. The system shall acknowledge uploaded answer scripts within 5 seconds.

depending on script size and complexity. 
4. The system shall support at least 50 concurrent users without significant degradation in 
response time. 
5. The system shall support batch processing of multiple answer scripts. 
6. The system shall retrieve student reports and analytics within 5 seconds. 
7. The system shall maintain a minimum 99% system availability, excluding scheduled 
maintenance. 
8. The system should support horizontal scaling to accommodate increasing workloads. 
9. The database shall use indexing and optimization techniques to ensure efficient data retrieval. 
 
5.2 Safety Requirements 
The MarkNex system must ensure safe handling of academic data and prevent data loss: 
1. The system shall automatically back up evaluation data at regular intervals. 
2. The system shall prevent accidental deletion of uploaded scripts without user confirmation. 
3. The system shall preserve original answer scripts even if AI processing fails. 
4. The system shall maintain system logs for uploads, evaluations, and manual modifications. 
5. The system shall implement proper error-handling mechanisms to prevent data corruption. 
6. The system shall support data recovery in the event of system failure. 
7. The system should notify administrators in case of critical failures. 
 
5.3 Security Requirements 
The MarkNex system must protect user credentials and student academic records: 
1. The system shall enforce secure authentication using username and password. 
2. The system shall store passwords using secure hashing and salting techniques. 
3. The system shall implement role-based access control for Teachers and Administrators. 
4. The system shall ensure that users can only access data related to their assigned classes. 
31 
 
5. All data transmission between client and server shall use HTTPS encryption. 
6. The system shall automatically terminate inactive sessions after a defined timeout period. 
7. The system shall log all login attempts, uploads, and manual mark changes. 
8. The system must prevent unauthorized access to student records. 
9. The system should implement protection against common web vulnerabilities (e.g., SQL 
injection, cross-site scripting).

5.5 Business Rules 
The following business rules shall govern the operation of the MarkNex system: 
1. Only registered Teachers and Administrators shall be allowed to access the system. 
2. Each uploaded answer script must be linked to a valid student identifier. 
3. The AI module shall assign marks according to predefined marking schemes. 
32 
 
4. Teachers shall have the authority to modify AI-assigned marks when necessary. 
5. The system shall automatically recalculate total marks after any modification. 
6. Answers with confidence scores below the defined threshold must be flagged for manual review. 
7. Historical evaluation records shall not be permanently deleted without administrative approval. 
8. The confidence threshold value shall be configurable by the Administrator. 
9. Reports generated by the system shall comply with institutional grading policies.

evaluations, and manual mark modifications for accountability and traceability.

authentication, file management, and AI evaluation modules to be reused or extended in future 
academic assessment systems. 
 
Appendix A: Glossary 
This section defines key terms, acronyms, and abbreviations used in the MarkNex SRS to ensure a 
common understanding among all stakeholders. 
1. AI: Artificial Intelligence. 
2. API: Application Programming Interface, used for communication between the backend and the 
Multimodal LLM. 
33 
 
3. Confidence Score: A numerical value generated by the AI indicating the statistical certainty of 
the assigned mark. 
4. DFD: Data Flow Diagram, used to visualize the flow of information within the system. 
5. Human-in-the-Loop: A model of interaction where the AI performs tasks but requires human 
intervention (the teacher) for validation or error correction. 
6. LLM: Large Language Model; specifically, a Multimodal LLM that can process both text and 
images (scanned scripts). 
7. Marking Scheme: A predefined set of criteria or model answers used to evaluate student 
responses. 
8. Multimodal: The ability of an AI model to process different types of data (e.g., images of 
handwriting and digital text) simultaneously. 
9. OCR: Optical Character Recognition (though MarkNex aims to exceed traditional OCR 
limitations). 
10. RDBMS: Relational Database Management System (e.g., MySQL or PostgreSQL). 
11. SRS: Software Requirements Specification. 
12. UI/UX: User Interface and User Experience.
